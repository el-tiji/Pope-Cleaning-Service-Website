You are a senior full-stack developer working on the Pope Cleaning Services website/app.

MAIN OBJECTIVE
Build a complete, secure and functional ADMIN dashboard ecosystem for Pope Cleaning Services.

The current public website already has a Book Now / Request a Cleaning Quote form where customers submit their cleaning request without seeing prices. Now we need an ADMIN-only system where the business can manage those quote requests, generate internal price suggestions, respond to customers, schedule jobs, track payments and view operational/financial statistics.

This ADMIN system is critical for the business. It must help Pope Cleaning Services avoid losing quote requests, respond faster, convert leads into paid jobs and manage operations more professionally.

IMPORTANT BUSINESS CONTEXT
Pope Cleaning Services is a cleaning business based in Perth, Western Australia.

Core services:

* Regular Home Cleaning
* Spring / Deep Cleaning
* Vacate / End of Lease Cleaning
* Office / Commercial Cleaning
* Carpet & Upholstery Steam Cleaning
* Tile & Grout Cleaning
* Pressure Cleaning
* Custom Cleaning Requests

Public customers should NOT see internal price calculations.

The ADMIN should be able to:

* Review quote requests.
* Use an internal estimator based on the existing pricing calculator logic.
* Adjust the suggested price manually.
* Save a final quote.
* Contact the customer by their preferred method.
* Convert accepted quotes into bookings.
* Track service status.
* Track payment status.
* View revenue and operational statistics.

AUTH IMPLEMENTATION
Inspect the current project stack first.

If Supabase is already used:

* Use Supabase Auth.
* Create/use a `profiles` table.
* Store role in profile.
* Protect admin routes by checking role = `admin`.
* Use Supabase Row Level Security where applicable.

If Firebase is already used:

* Use Firebase Auth.
* Store role in Firestore or custom claims.
* Protect admin reads/writes with security rules.

If Node/Express backend exists:

* Implement secure session or JWT auth.
* Hash passwords with bcrypt or equivalent.
* Protect admin API routes server-side.

If no auth/backend exists:

* Implement a secure scalable auth approach compatible with the current project.
* Prefer Supabase Auth + Postgres if feasible.
* Otherwise create backend auth with secure password hashing and protected routes.
