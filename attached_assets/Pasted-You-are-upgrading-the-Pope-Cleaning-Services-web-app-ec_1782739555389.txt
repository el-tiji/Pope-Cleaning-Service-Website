You are upgrading the Pope Cleaning Services web + app ecosystem.

GLOBAL OBJECTIVE
Build a complete, production-ready authentication, authorization, customer portal and admin operations ecosystem without breaking the current public website.

IMPORTANT CONSTRAINTS
- Preserve the existing public site design, branding, colours, current page layout and current booking/public quote-request experience unless explicitly required for integration.
- Do NOT create a public “admin signup”.
- Do NOT rely only on frontend route hiding for permissions.
- Do NOT store auth tokens in localStorage or sessionStorage.
- Do NOT duplicate pricing logic in two different places.
- Build this as a secure, scalable system with one identity layer and role-based / attribute-based access control.
- Use the current stack if already present in the repo. If a component is missing, add the minimal robust solution that integrates cleanly with the existing codebase.

PRIMARY PRODUCT DECISION
Implement one shared authentication system with protected role-specific areas:

1. Public website
   - Existing marketing pages remain public.
   - Existing public booking / quote request remains public unless already planned otherwise.
   - Public users can create an account or sign in.

2. Customer portal
   - Authenticated customers see only their own properties, bookings, statuses, photos, quote history and communication preferences.
   - Customers cannot see or enumerate any data from other users.

3. Admin portal
   - Admin users sign in through the same auth system but are redirected to a protected admin application area.
   - Admin must have stronger security controls than customers.
   - Admin can review quote requests, bookings, customer profiles, property details, uploaded photos, payment states and internal pricing suggestions.

PASSWORD AND ACCOUNT RULES
- Passwords must be hashed with Argon2id.
- If Argon2id is not available in the project stack, use scrypt.
- Never store passwords in plaintext.
- Password policy:
  - if an account uses password-only auth, require a strong minimum length;
  - if admin MFA is mandatory, password length can be adjusted accordingly, but keep it strong.
- Allow long passwords and do not force fragile composition rules.
- Add server-side rate limiting for:
  - login
  - signup
  - forgot password
  - reset password
  - MFA verification
- Prevent user enumeration:
  - login, forgot password and account recovery responses must not reveal whether an email exists.
- Forgot password tokens must be:
  - cryptographically random
  - single-use
  - expiry-limited
  - stored securely
- Do not automatically log the user in right after reset; require normal login flow.

SESSION AND TOKEN SECURITY
Use secure server-backed session handling or HttpOnly cookie-based auth:
- cookies must be:
  - HttpOnly
  - Secure
  - SameSite=Lax or Strict depending on route needs
- regenerate session ID after:
  - login
  - privilege change
  - password change
  - important account-security changes
- do not store auth credentials in localStorage
- implement server-side session invalidation on logout
- allow “log out all sessions” from account security settings

INTERNAL LIVE ESTIMATED PRICE CALCULATOR FOR ADMIN
Move the pricing engine into an admin-use operational flow.

CRITICAL RULE:
The pricing calculation logic must exist in a shared backend service so it can be called consistently.

Admin pricing workflow:
1. Admin opens a quote request / booking
2. System reads:
   - property type
   - cleaning type
   - size
   - characteristics
   - extras
   - access / logistics
   - cleaning frequency
3. System runs the internal estimator
4. System shows:
   - suggested base amount
   - line items / factors
   - frequency effects
   - any surcharge suggestions
   - notes explaining the suggestion
5. Admin can:
   - accept the suggestion
   - override the amount
   - edit line items
   - add notes
6. Final quote version is saved
7. Admin chooses delivery channel
8. System sends quote and stores communication log

The estimator suggestion must be editable, but all changes must be auditable.
